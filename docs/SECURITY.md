## 身份认证与授权

- 身份认证统一通过 `{{IDENTITY_PROVIDER_OR_MECHANISM}}`；令牌和会话有明确有效期、吊销及轮换策略。
- 每个受保护操作在服务端执行授权；不得仅依靠前端隐藏按钮。
- 对象级权限必须按资源所有者、组织和角色验证，防止通过修改 ID 访问他人数据。
- 高权限操作采用最小权限、职责分离和可审计审批。
- 认证失败和权限拒绝使用稳定错误码，避免泄露账户存在性和内部权限结构。

## 输入、输出和文件

- 在信任边界校验类型、长度、范围、格式及业务约束；正则只用于适合的格式检查，不能替代解析器和业务校验。
- SQL 使用参数化查询或安全 ORM，不拼接外部字符串。
- HTML 使用上下文相关输出编码，模板默认转义；富文本只允许经过可信清洗器处理的内容。
- Shell 命令使用参数数组和受限允许列表，避免把输入拼接进命令字符串。
- URL 和目标主机必须校验，防止 SSRF；路径要规范化并限制在允许目录内。
- 文件上传校验大小、实际类型、扩展名和内容，使用随机存储名，禁止直接执行上传文件。

## 数据保护与隐私

- 数据分类：`{{PUBLIC_INTERNAL_CONFIDENTIAL_RESTRICTED_DEFINITIONS}}`。
- 传输使用受支持的 TLS；静态敏感数据按分类加密，密钥与数据分离。
- 只采集完成业务所需的数据，保留期和删除规则为 `{{RETENTION_POLICY}}`。
- 生产个人数据不得直接进入开发或测试环境；确需使用时先脱敏并获得相应授权。
- 日志和追踪不得含密码、Token、Cookie、验证码、私钥或完整敏感身份信息。
- 对导出、批量查询和高权限读取建立速率限制、审计和异常检测。

## 秘密与配置

- 秘密存储在 `{{SECRET_MANAGER}}`，通过运行环境注入；禁止提交到 Git、镜像层、CI 日志和文档。
- 对凭证设置最小权限、过期或轮换机制；离职、泄漏或权限变更时及时撤销。
- 仓库中的示例配置只能包含无效占位符；真实 `.env` 文件必须被忽略。
- 发现疑似泄漏时先撤销或轮换凭证，再清理暴露副本并调查访问记录；仅删除 Git 中的文本不能使凭证安全。

## 依赖与构建

- 依赖由锁文件固定；CI 进行漏洞、许可证和秘密扫描。
- 仅从可信源下载依赖和构建工具，验证来源与校验信息。
- 构建和部署身份使用最小权限，生产发布需要可追溯的审批与产物来源。
- 对高危依赖漏洞记录暴露范围、缓解措施、负责人和修复期限。

## 审计与事件响应

- 记录登录、权限变更、敏感数据访问、导出、删除、配置变更和管理操作。
- 审计事件包含操作者、时间、对象、动作、结果和关联 ID，但不包含秘密。
- 安全事件联系渠道：`{{SECURITY_CONTACT}}`；分级标准：`{{SEVERITY_RULES}}`。
- 事件处置顺序：控制影响、保全证据、撤销受影响凭证、修复漏洞、按适用政策通知相关方、复盘。
- 对外通知和数据泄露处理遵循适用法律及组织流程；本模板不能替代具体法域评估。
