## 超时、重试与隔离

- 每个外部调用必须有连接、读取和总体超时，且不得超过上游请求剩余时间预算。
- 仅对瞬时、可恢复错误重试；必须设置次数上限、指数退避与抖动。
- 写操作重试须有幂等键或去重机制；不能靠“通常不会重复”保证正确性。
- 下游故障应通过限流、熔断、队列上限或舱壁隔离，避免级联故障。
- 对关键降级路径说明用户可见行为、数据一致性和恢复步骤。

## 监控和告警

- 监测请求量、错误率、延迟、饱和度以及核心业务完成率。
- 关键异步流程监测积压、处理耗时、重试和死信数量。
- 告警根据用户影响、错误预算燃烧或持续异常设置阈值，并有负责人和运行手册。
- 每个用户请求能通过 `requestId` 或 `traceId` 关联日志和追踪。
- 日志、指标标签和追踪属性不得包含秘密或高基数个人数据。

## 故障处理与复盘

1. 先恢复用户服务并限制影响，再定位根因。
2. 明确事件指挥、沟通、调查和操作角色，关键操作留痕。
3. 按 `{{INCIDENT_SEVERITY_RULES}}` 分级并按 `{{COMMUNICATION_POLICY}}` 沟通。
4. 事后复盘包含时间线、用户影响、根因、检测缺口、有效措施和带负责人的改进项。
5. 改进项进入执行计划或技术债清单，并跟踪到验证完成。
