## 问题与目标

假设：首次进入产品的用户不了解完成首个关键任务的路径。需要通过用户访谈和漏斗数据验证，不应直接当作事实。

- 目标用户：`{{首次注册且尚未完成核心任务的用户}}`。
- 目标行为：`{{在首次会话中完成一个核心任务}}`。
- 成功指标：`{{首次会话核心任务完成率，注明基线、目标和观察期}}`。
- 守护指标：`{{退出率、投诉率、完成时间}}`。

## 范围

- 引导用户识别下一步可执行动作，并显示可跳过或返回的入口。
- 在中断后恢复合理进度，避免重复强迫观看。
- 明确空状态、错误状态、权限不足和移动端表现。

不包含：`{{高级功能培训、长期营销消息等；按项目实际情况调整}}`。

## 验收示例

- [ ] 首次符合条件的用户进入后能看到清晰的第一步和退出方式。
- [ ] 用户跳过后不会在同一条件下被反复强制进入引导。
- [ ] 引导所需服务失败时，用户仍能访问产品核心功能。
- [ ] 键盘用户和读屏用户能完成或跳过引导。
- [ ] 事件埋点能区分开始、每步完成、跳过和最终完成。
